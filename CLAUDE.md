# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`serintode` searches for ODEs that annihilate an integer series (the input is a list of coefficients, one per line). It tries successively larger ODE orders / polynomial-coefficient degrees / nonlinearity depths, building a matrix whose null vectors correspond to candidate ODEs, and computing that nullspace via IML (mod-p with verification).

Single dispatcher binary `serintode` with subcommands:

- `serintode linear <input>` — linear ODE search. In `modes_linear.c`.
- `serintode nonlin <input> [--lookup-dir=PATH]` — algebraic (nonlinear) ODE search. In `modes_nonlin.c`. With `--lookup-dir`, reads pre-generated term-exponent tables from `<PATH>/o<n>d<p>.txt`; without it, enumerates compositions in-process via `combs()`.
- `serintode makelookup <max-order> <num-coeffs>` — generates the lookup tables. In `modes_makelookup.c`, sharing `combs()` from `modes_nonlin.h`.

Shared code:
- `io.{c,h}` — series parser, polynomial-coefficient pretty-printer (callback API), `s_malloc`/`s_calloc`. `MAX_LINE_LENGTH` is a `#define` here.
- `solver.{c,h}` — IML `kernelMP` wrapper with spurious-zero check, `select_best_linear`, `select_best_nonlin`.
- `serintode.{c,h}` — dispatcher main, `mode_descriptor` struct.

Out of scope: `serintode_flint.c` (FLINT version, slower and unverified), `old/` (archival prototypes).

## Build

```
make            # builds the serintode binary
make test       # runs the regression suite (linear + nonlin)
make clean
```

Override `IML_DIR=/path/to/iml` if IML lives somewhere other than `/home/ralf/math/iml`. Library install instructions (IML, GMP, ATLAS) are in `README.txt`.

## How to run

```
./serintode linear     <input-file> [--checks=N] [--min-order=N] [--max-coeffs=N]
./serintode nonlin     <input-file> [--checks=N] [--min-order=N] [--max-coeffs=N]
                                    [--min-depth=N] [--max-depth=N] [--lookup-dir=PATH]
./serintode makelookup <max-ode-order> <num-coeffs>     # writes lookuptables/o<n>d<p>.txt
```

Defaults match the legacy programs: linear `--checks=6 --min-order=1 --max-coeffs=400`; nonlin `--checks=0 --min-order=1 --max-coeffs=100 --min-depth=1 --max-depth=10`.

Input files are plain text, one base-10 integer per line; leading zero coefficients are stripped automatically. `tests/central_binomials.txt` is a known-good linear regression input (OEIS A000984; expected ODE `(1-4x)y' - 2y = 0`).

Output filename: `<input>_<mode>_<NUM_CHECKS>-checks.txt`, in Maple syntax, also echoed to stdout. `make test` diffs against the baselines in `tests/expected/`.

## Architecture notes worth knowing before editing

**The main loop structure is the same across modes**: outer loop over ODE order `n`, inner loop builds matrix `M` whose rows encode the ODE-applied-to-series constraints, then `compute_nullspace` (in `solver.c`) computes the right nullspace and runs the spurious-zero check, then a per-mode selector picks a "best" null vector. Linear and Mahler use `select_best_linear` (tiebreak: max poly degree, then nonzero terms). Nonlin uses `select_best_nonlin` (tiebreak: orders used, then max depth, then max poly order, then terms).

**The IML constraint** (`README.txt`): IML reduces mod a random 15–19-bit prime and uses CBLAS doubles internally, which caps `ceil(n/2)*(p-1)^2 + (p-1) ≤ 2^53 - 1`. This is why `--max-coeffs` matters — too large and IML's row-echelon step loses precision.

**Nonlin term enumeration** uses the recursive `combs()` function (credited to Richard Brent) to enumerate compositions — the multi-indices for terms like `y^a * (Dy)^b * (D²y)^c`. `--lookup-dir=PATH` reads precomputed tables from `PATH/o<n>d<p>.txt` (generated by `serintode makelookup`); without the flag, `combs()` runs in-process every iteration.

**Pretty-printer** is split: `print_ode` in `io.c` walks the null vector and emits the polynomial-coefficient block (`(...)` with sign / leading-coeff / `x^k` handling, identical across modes). The mode-specific monomial that follows (`*y(x)`, `*diff(y(x),x)`, `*(y(x))^2`, etc.) is emitted by a per-mode callback (`print_monomial_linear`, `print_monomial_nonlin`).

**Bound formulas** (derived in `README.txt`):
- `MAX_POLY_ORDER = floor((NUM_COEFFS - NUM_CHECKS - ODE_ORDER) / (ODE_ORDER + 1)) - 1`
- `MAX_ODE_ORDER = floor((NUM_COEFFS - NUM_CHECKS) / 2) - 1`

## Adding a new mode

1. Create `modes_<name>.c` with: a `*_run(int argc, char *argv[])` function (parses its own flags via `getopt_long`, calls `read_series`, builds matrix, calls `compute_nullspace`, calls a selector, calls `print_ode` with a per-mode `print_monomial_*` callback) and `const mode_descriptor mode_<name> = { .name = "<name>", .description = "...", .run = <name>_run };`.
2. Add `extern const mode_descriptor mode_<name>;` to `serintode.h`.
3. Add `&mode_<name>,` to `all_modes[]` in `serintode.c`.
4. Add `modes_<name>.o` to `OBJS` in the `Makefile`.
5. Add a regression input under `tests/`, generate the expected output, commit it under `tests/expected/`, extend `make test`.

The forthcoming Mahler mode (see `TODO.md`) is the next planned addition; it'll reuse `select_best_linear`.

## Known issues / gotchas

- `MAX_LINE_LENGTH` (in `io.h`) is the heap-allocated input-line buffer size. Increase if coefficients have ≥99999 digits.
- `--max-coeffs` drives a `MAX_COEFFS * MAX_COEFFS` `mpz_t` matrix allocation, which grows quadratically.
